|---|---|---|
| 무엇을 보나 |  | 정확한 열·단위·대상 |
| 언제 알았나 |  | 공개 시각·사용 가능일 |

| 무엇이면 틀렸다고 하나 |  | 손계산·기준선·미래 절단·홀드아웃 |

## 4. 코덱스에 보낼 첫 요청 바꾸기

약한 요청:

> 이 전략을 백테스트해 줘.

감사 가능한 요청에는 최소한 아래 항목을 넣는다.

- [ ] 실제 시장 결론을 내리지 않는 작은 합성 표부터 쓴다.
- [ ] 각 값이 알려진 시각과 신호 시각을 분리한다.
- [ ] 신호 다음 시점의 가격으로 체결한다고 고정한다.
- [ ] 거래별 감사표에 입력·신호·체결·비용·손익을 남긴다.
- [ ] 미래 행을 잘라도 과거 결과가 같은지 검사한다.
- [ ] 비용을 높인 대조군과 시도 원장을 남긴다.
- [ ] 홀드아웃은 규칙을 고른 뒤 한 번만 연다.

내가 다시 쓴 요청:

## 5. 결과를 받을 때의 보류 조건

아래 중 하나라도 해당하면 수익률 해석을 보류한다.

- [ ] 거래별 행이 없고 최종 수익률만 있다.
- [ ] 값이 언제 알려졌는지 기록이 없다.
- [ ] 신호 가격과 체결 가격이 같은데 이유가 없다.
- [ ] 시험한 조합 수가 없고 가장 좋은 조합만 남았다.
- [ ] 비용을 바꿨을 때 거래 수나 총수익까지 함께 바뀐다.
- [ ] 홀드아웃을 여러 번 열어 규칙을 다시 골랐다.

완료 조건: 다른 사람이 이 종이만 읽고도 같은 입력·규칙·행동 가정을 구현할 수 있고,
무엇이 아직 미정인지 같은 위치에서 찾을 수 있다.
