    069500이 KODEX 200인지 먼저 확인한다

    실습 대상은 KODEX 200, 종목코드는 069500이다. 삼성자산운용의 KODEX 200 공식 상품 페이지는 상품명과 종목코드, KOSPI 200 지수를 추적한다는 설명을 함께 제공한다. 숫자 코드만 보고 데이터를 받지 말고, 상품명과 코드를 공식 상품 페이지에서 먼저 맞춘다.

    한국거래소의 OPEN API 서비스 목록에는 2010년 1월 4일 이후의 ETF 일별매매정보가 있다. 다만 서비스 이용방법에 따르면 회원가입과 로그인, API 인증키 신청, 관리자 승인, 개별 서비스 신청과 승인이 필요하다. 공식 거래소 경로는 중요하지만, 가입과 승인을 마치지 않은 초보자가 15분 안에 따라 할 첫 실습에는 맞지 않는다.

    첫 실습은 공급자를 적은 NAVER:069500으로 고정한다

    FinanceDataReader 공식 저장소는 국내 종목 가격을 읽는 DataReader와 NAVER: 접두사를 문서화한다. 이 차시에서는 다음 호출을 쓴다.

    fdr.DataReader("NAVER:069500", "2024-01-02", "2024-03-29")

    종목코드만 069500으로 써도 2026-08-27의 FinanceDataReader는 NAVER 경로를 기본값으로 선택했다. 그러나 기본값은 라이브러리 버전에서 바뀔 수 있다. NAVER:069500처럼 공급자를 직접 적으면 어떤 경로를 사용했는지 코드만 보고도 알 수 있다.

    표 2공식성, 접근 절차, 공급자 명시 여부를 기준으로 고른 데이터 경로.
    경로 장점 첫 실습에서의 판단
    KRX OPEN API 거래소가 제공하는 공식 ETF 일별매매정보다 인증키와 서비스 승인이 필요해 기본 실습에서는 사용하지 않는다
    FinanceDataReader NAVER:069500 짧은 Python 호출로 지정 기간을 받을 수 있다 이번 영상의 고정 경로로 사용하고 버전·실행일을 함께 기록한다
    종목코드만 069500 코드가 짧다 내부 기본 공급자가 드러나지 않아 사용하지 않는다

    FinanceDataReader는 거래소 공식 API가 아니라 여러 웹 데이터 경로를 읽기 쉽게 묶은 오픈소스 도구다. 공급 사이트의 응답 형식이나 라이브러리 구현이 바뀌면 열과 값도 달라질 수 있다. 또한 이 도구가 반환한 Close라는 열 이름만 보고 거래소 원시 종가인지, 어떤 조정이 적용됐는지까지 단정하지 않는다. 가격 열의 세부 의미와 공급자 간 차이는 다음 과정인 「노트북과 데이터 문해력」에서 다룬다.

    notebooks/kodex200_price.ipynb CSV를 읽고 검사하며 표와 그래프를 표시한다 파일 경로와 열 이름이 CSV와 일치한다

    노트북의 핵심 코드는 수집과 읽기를 분리한다

    pandas 공식 문서는 DataFrame.to_csv()로 표를 CSV에 쓰는 방법을, read_csv() 문서는 그 파일을 다시 표로 읽는 방법을 설명한다. 노트북의 핵심 흐름은 다음과 같다.

    from pathlib import Path

import FinanceDataReader as fdr
import matplotlib.pyplot as plt
import pandas as pd

START = "2024-01-02"
END = "2024-03-29"
SYMBOL = "NAVER:069500"

cwd = Path.cwd()
project_root = cwd.parent if cwd.name == "notebooks" else cwd
csv_path = project_root / "data" / "kodex200_price.csv"
csv_path.parent.mkdir(parents=True, exist_ok=True)

if not csv_path.exists():
    downloaded = fdr.DataReader(SYMBOL, START, END)
    if downloaded.empty:
        raise RuntimeError("가격 데이터가 비어 있습니다.")
    downloaded.index.name = "Date"
    downloaded.to_csv(csv_path)

prices = pd.read_csv(csv_path, parse_dates=["Date"])
required = {"Date", "Open", "High", "Low", "Close", "Volume", "Change"}
if not required.issubset(prices.columns):
    raise RuntimeError(f"필수 열이 없습니다: {required - set(prices.columns)}")
if prices["Date"].min() != pd.Timestamp(START):
    raise RuntimeError("첫 날짜가 요청과 다릅니다.")
if prices["Date"].max() != pd.Timestamp(END):
    raise RuntimeError("마지막 날짜가 요청과 다릅니다.")

display(prices.head())
display(prices.tail())

fig, ax = plt.subplots(figsize=(10, 4))
ax.plot(prices["Date"], prices["Close"], color="#0F2C59", linewidth=2)
ax.set(title="KODEX 200 Close", xlabel="Date", ylabel="Close")
ax.grid(alpha=0.2)
plt.show()

    첫 실행에서는 CSV가 없으므로 데이터를 받아 저장한다. 그 뒤에는 저장된 CSV를 읽는다. 이 구조 덕분에 노트북을 다시 실행할 때 공급자 응답이 바뀌거나 잠시 인터넷이 끊겨도 이미 받은 실습 데이터로 표와 그래프를 확인할 수 있다. 데이터를 새로 받고 싶다면 기존 파일을 덮어쓰는 대신 날짜와 공급자를 확인한 뒤 의도적으로 갱신해야 한다.

    2026-08-27의 기록된 실행 결과

    위 호출을 Python 3.12.3의 격리 환경에서 실행한 결과, 2024-01-02부터 2024-03-29까지 61행이 반환됐다. 열은 Open, High, Low, Close, Volume, Change였고, 인덱스 이름을 Date로 저장했다. 첫 행의 Close는 34,541, 마지막 행은 36,123이었다.

    표 5FinanceDataReader 0.9.202로 2026-08-27에 확인한 실행 기록.
    항목 기록된 값 확인 이유
    행 수 61 파일이 비어 있지 않고 지정 기간의 거래일 자료가 들어왔는지 본다
    첫 날짜 2024-01-02 시작 경계가 요청과 같은지 본다
    마지막 날짜 2024-03-29 종료 경계가 요청과 같은지 본다
    첫 Close 34,541 노트북 표와 기록된 실행을 대조한다
    마지막 Close 36,123 그래프 끝점과 표의 마지막 행을 대조한다
    최저 Close 31,248 (2024-01-17) 선 그래프의 가장 낮은 지점이 표 안에 있는지 본다
    최고 Close 36,123 (2024-03-29) 선 그래프의 가장 높은 지점이 마지막 행과 맞는지 본다

    61이라는 숫자를 영구 정답처럼 외우지는 않는다. 공급자가 과거 자료를 정정하거나 FinanceDataReader의 처리 방식이 바뀌면 나중의 실행 결과가 달라질 수 있다. 촬영일에는 같은 호출을 새 환경에서 다시 실행하고, 행 수·열·첫 날짜·마지막 날짜를 이 표와 대조한다. 값이 달라졌다면 실패를 숨기지 말고 공급자와 버전을 기록한 뒤 리포트와 화면을 함께 갱신한다.

    표와 그래프는 서로 다른 오류를 찾는다

    표에서는 열 이름, 날짜, 첫 행과 마지막 행을 정확히 읽을 수 있다. 그래프에서는 시간 순서가 뒤집혔거나 값이 한 줄로 뭉개졌거나 결측 구간이 큰 문제를 빠르게 발견할 수 있다. Matplotlib의 plot 공식 문서는 x와 y 값을 선으로 잇는 기본 동작을 설명한다. 이 실습에서 그래프는 투자 신호가 아니라 CSV를 날짜 순서로 읽어 Close 열을 표시했다는 확인 화면이다.

    새 커널에서 전체 셀을 실행해야 숨은 순서 의존성이 드러난다

    위에서 아래로 한 번에 실행해 본다

    노트북은 셀을 원하는 순서로 실행할 수 있다. 편리하지만, 앞서 실행한 셀의 변수가 메모리에 남아 있으면 현재 파일만으로는 실행되지 않는 문제를 놓칠 수 있다. VS Code의 Jupyter 공식 문서는 오른쪽 위에서 커널을 선택하고, 노트북 도구 모음에서 커널을 다시 시작하거나 Run All로 모든 셀을 실행하는 기능을 안내한다.

    다음 순서로 확인한다.

    1. kodex200_price.ipynb를 저장한다.
    2. 오른쪽 위 커널이 영상 3에서 만든 .venv인지 확인한다.
    3. 노트북 도구 모음에서 Restart Kernel을 선택한다.
    4. Run All을 눌러 첫 셀부터 마지막 셀까지 기다린다.
    5. 빨간 오류가 없고, 표의 첫·마지막 날짜와 Close 그래프가 다시 보이는지 확인한다.

    여기서 “같은 결과”는 인터넷의 값이 영원히 고정된다는 뜻이 아니다. 이 노트북은 첫 수집 결과를 로컬 CSV에 저장하고 이후 셀에서 같은 파일을 읽기 때문에, 같은 CSV와 같은 코드가 같은 표와 그래프를 만드는지를 확인한다. CSV를 의도적으로 갱신했다면 새 파일의 공급자, 기간, 열을 다시 검사한다.

    오류가 나면 Codex에 오류 메시지를 그대로 보여 주되 “고쳐 줘”만 쓰지 않는다. 어떤 셀에서 멈췄는지, 기대한 파일이 무엇인지, 현재 파일이 실제로 존재하는지를 함께 전달한다. 수정 뒤에는 다시 커널을 시작하고 Run All을 반복한다. 중간 셀 하나만 성공한 것으로 끝내지 않는다.
