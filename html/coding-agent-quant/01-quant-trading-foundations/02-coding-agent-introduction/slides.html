01코딩 에이전트를 잘 쓰려면 맡길 일과 사람이 직접 판단할 일을 먼저 나누어야 합니다.02파일을 만들고 고치거나 명령을 실행하는 반복 작업은 에이전트에게 맡길 수 있습니다.03무엇을 만들지, 어디까지 허용할지, 결과가 투자 목적에 맞는지는 사람이 판단합니다.

코딩 에이전트는 확인하고 실행하는 과정을 되풀이한다

작업 순환은 세 장면으로 읽는다

01앞의 순환을 세 장면으로 나누어 보겠습니다.02현재 상태에서는 요청과 열린 파일과 앞선 실행 결과를 살핍니다.03다음 작업에서는 필요한 파일 도구나 명령 도구를 골라 실행합니다.04실행 결과에서는 성공과 오류를 확인하고, 필요하면 다시 앞 단계로 돌아갑니다.

대화형 응답과 에이전트 작업은 남는 결과가 다르다

01대화형 응답과 에이전트 작업은 남는 결과부터 다릅니다.02왼쪽은 설명과 예시 코드를 건네고 사용자가 옮겨 실행하는 흐름이고, 오른쪽은 에이전트가 허용된 폴더의 파일을 고치고 명령 결과까지 남기는 흐름입니다.

차이는 설명보다 작업의 흔적에서 드러난다

01두 방식을 네 기준으로 비교합니다.02대화형 응답은 붙여 넣은 자료를 보지만, 에이전트는 열린 파일과 관련 파일도 참고합니다.03대화형 응답은 방법을 제안하고, 에이전트는 파일 수정과 명령 실행까지 이어 갑니다.04대화형 응답에는 대화가 남고, 에이전트 작업에는 실제 파일과 실행 기록도 함께 남습니다.05어느 방식을 쓰든 사람은 목표를 정하고 결과를 검토합니다.

01이제 에이전트가 참고할 작업 문맥을 좁히고, 원하는 결과를 구체적으로 요청하는 방법을 살펴보겠습니다.

에이전트는 문맥과 도구를 거쳐 확인 가능한 결과를 남긴다

에이전트의 행동마다 확인할 기록이 남아야 한다

01에이전트의 행동마다 사람이 확인할 기록이 남아야 합니다.02파일을 찾았다면 읽은 파일과 작업 범위를 봅니다.03파일을 만들거나 고쳤다면 이름과 바뀐 내용을 확인합니다.04명령을 실행했다면 실제 명령과 종료 결과를 봅니다.05오류를 고쳤다면 실패 원인과 수정 내용을 대조합니다.06완료 보고를 받았다면 파일과 검사 결과와 남은 문제가 실제 결과와 맞는지 확인합니다.

좋은 작업 요청에는 다섯 가지가 들어간다

01좋은 작업 요청은 다섯 요소로 구성됩니다.02무엇을 위한 작업인지 목적을 말하고, 참고할 문맥과 지켜야 할 제약을 정하며, 만들어야 할 결과물과 완료를 확인할 방법까지 알려 줍니다.03파이썬 문법을 몰라도 이 다섯 가지는 구체적으로 말할 수 있습니다.

막연한 말에는 빠진 조건이 있다

막연한 부탁을 확인 가능한 작업으로 바꾼다

01예를 들어 막연한 부탁을 확인 가능한 작업으로 바꿔 보겠습니다.02코덱스 이백 차트를 만들어 달라는 말만으로는 종목 코드와 기간과 저장 위치와 완료 조건을 알 수 없습니다.03가격을 씨에스브이 파일에 저장하고 노트북에서 표와 종가 그래프로 보이게 하며, 사용할 폴더와 완료 보고 항목까지 정하면 결과를 대조할 수 있습니다.

사람과 에이전트의 역할을 나눈다

01다음으로 사람과 에이전트가 어떤 일을 맡고, 마지막 책임은 누구에게 남는지 나누어 보겠습니다.

사람이 방향을 정하고 에이전트가 정해진 일을 수행한다

사람은 방향과 판단을, 에이전트는 구현과 반복을 맡는다

01역할을 다섯 단계로 나눕니다.02목표는 사람이 정하고 에이전트가 실행 단계를 제안합니다.03범위는 사람이 정하고 에이전트가 그 안에서 도구를 씁니다.04금융 가정과 완료 조건은 사람이 확인하고 에이전트가 파일을 만듭니다.05결과의 투자 의미는 사람이 판단하고 에이전트가 검사 기록을 정리합니다.06최종 결정은 사람이 내리고 에이전트는 요청에 따라 다시 작업합니다.

파일 작업을 맡겨도 투자 판단까지 맡기는 것은 아니다

완료 여부와 권한을 직접 확인한다

01마지막으로 에이전트의 완료 보고를 어떻게 확인하고, 권한을 어디까지 허용할지 살펴보겠습니다.

완료 보고에서 멈추지 않고 다섯 가지 증거를 확인한다

01완료 여부는 요약 문장 하나가 아니라 다섯 가지 증거를 따라 확인합니다.02실제 파일과 바뀐 내용, 실행한 명령, 화면에 나온 결과를 차례로 본 뒤, 처음 요청한 요구 조건과 모두 맞는지 대조합니다.

작업을 받으면 세 묶음으로 직접 확인한다

01작업을 받으면 확인할 내용을 세 묶음으로 나누면 쉽습니다.02먼저 요청한 파일이 실제로 있고 변경 내용이 허용한 범위 안인지 봅니다.03다음으로 명령을 실제로 실행했고 표와 그래프와 오류를 직접 볼 수 있는지 확인합니다.04마지막으로 종목과 기간과 파일 형식과 표시 내용이 처음 요청과 같은지 대조합니다.
